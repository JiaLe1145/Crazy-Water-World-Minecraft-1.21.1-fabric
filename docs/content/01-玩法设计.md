## 1. 核心循环

`[原方案]` 玩家在限定海域内海上木筏生存，海域不定期刷新物资装备，出现不同事件，各队木筏之间可对抗，不断收集物资强化本队木筏，存活到最后。

细化后的单局动线（目标 8–15 分钟）：

```
大厅报名 → 分队(30s) → 出生等角分布 → 抢首轮物资(0-2min)
   → 建造/生产/招募(2-6min) → 黑海压缩(6-11min) → 被迫接敌(8-13min)
   → 最后两队/夺筏决战 → 存活队胜 → 结算面板 → 回大厅
```

一局内的三层决策（这是玩法深度所在）：
- **资源层**：这一轮刷新物资我去不去？去了会不会被黑海追上？
- **建造层**：把材料投到筏体扩展（更大建造区/更多设施）、还是投到武备（现在就去打）？
- **人力层**：幸存者数量 = 复活资格 + 生产力，但每天要吃要喝 → 招不招、招哪个职业。

## 2. 对局阶段与流程

`[新增·待批 A1]` 原方案没有开局流程，这是必须补的第一块骨架。

| 阶段 | 时长 | 内容 | 玩家状态 |
|---|---|---|---|
| `LOBBY` 大厅 | 常驻 | 报名、看战绩、聊天、观战 | 冒险模式，锁定在大厅区域 |
| `ENROLL` 报名/分队 | 30s | 自主分队（原方案要求），不满员自动补位/调平 | 大厅内可移动 |
| `READY` 准备 | 10s 倒计时 | 载入地图、锁定队伍、发放初始筏 | 传送进图，冻结输入 |
| `PLAY` 对局 | 8–15min | 主玩法，内含 4 段黑海压缩 | 生存模式，PVP 开 |
| `SETTLE` 结算 | 20s | 胜负、MVP、本局数据 | 冻结，可看面板 |
| `RETURN` | 5s | 传送回大厅，清理局内状态 | 回 `LOBBY` |

规则要点：
- **分队** `[已批准·原方案]`：玩家自主选队（通过队旗 UI 点选）。人数不均时按"先申请先进队 + 管理员调平命令"处理。
- **人数下限** `[新增·待批 A12]`：默认最少 2 队 × 2 人 = 4 人可开局；管理员可用命令强制开局或改预设。
- **中途加入** `[新增·待批 A13]`：本局禁止中途插队（会破坏平衡），进入观战等待下一局；掉线玩家保留 90s 重连席位，期间其幸存者仍在筏上工作（避免队友因掉线被连坐）。
- **状态清理**（关键）`[新增·待批 A13]`：结算后必须清除所有局内效果/属性/物品/建造权限，杜绝残留污染下一局。这条会写进架构的硬约束。

## 3. 海域机制与"黑海"

`[原方案]` 随游戏时间加入"黑海"，等价于大逃杀毒圈；同时随时间对部分海域区块提高物资品质，促使玩家距离越来越近、加快对抗。

`[新增·待批 A1]` 快节奏下的圈层与时间表（默认 12 分钟档）：

| 阶段 | 时间 | 半径 | 黑海伤害 | 物资品质倍数 | 设计意图 |
|---|---|---|---|---|---|
| P0 开荒 | 0:00–2:30 | 100%（默认 140 格） | 无 | ×1.0 | 允许两队以上各自采集 |
| P1 第一次压 | 2:30–3:30 收缩 | 65% | 0.5♥/s | ×1.2（内圈） | 逼迫回筏、开始有建造成果 |
| P2 第二次压 | 3:30–6:30 | 65%→40% | 1.0♥/s | ×1.5 | 中盘遭遇战窗口 |
| P3 第三次压 | 6:30–9:30 | 40%→20% | 2.0♥/s | ×2.0 | 物资集中，抢夺战 |
| P4 终局 | 9:30– | 20%→5% 且不再停 | 4.0♥/s | ×2.5（仅中心点） | 必须分胜负，杜绝拖局 |

- 半径 100% = 配置里的海域半径（默认建议 140 格，见 03 文档），5 档时长可切换成 8 分钟/15 分钟档。
- **伤害实现**：黑海内不只是掉血，还要叠加"减速 + 视野压暗 + 物资不可刷新"，让玩家对黑海有明确厌恶而不是把它当成可硬扛的 debuff（伤害曲线必须让"游回圈内"比"硬扛"划算）。
- **透明性** `[新增·待批 A1]`：每次压缩前 15s 全场公告 + 行动栏倒计时 + 边界粒子提示；下一圈的中心点提前公开。快节奏竞技里"预告过的圈"比"随机圈"更被接受。
- **物资品质随圈层提高** `[原方案]`：与上表品质倍数绑定，外圈只刷 Common/Rare，内圈才可能刷 Epic/Legendary。这条是原方案里推动"越来越近"的核心引擎，保留。

## 4. 木筏

`[原方案]` 玩家分队后在限定海域进行海上木筏生存，玩家必须不断收集物资强化自己队伍的木筏。
`[已批准]` 形态 = 锚定建造的多方块结构 + 离散位移（不做连续航行）。

### 4.1 初始筏与出生 `[新增·待批 A1]`
- 每队 1 艘筏（不是每人 1 艘）：`[原方案]` 明确是"各队木筏之间可以对抗"，因此队伍共享一筏。
- 初始筏 = **4×4 甲板**（用户 2026-11-06 裁决削弱到这里）+ 1 个队伍物资箱（内含 1 把木桨、8 木板、2 淡水）+ 1 面队旗（=筏心，见 4.3）。
  > 实现状态：4×4 甲板与筏心已落地（`domain/raft/RaftLayout` 按边长铺甲板并分配帆位/桨位，格子写死 ±3 的旧铺法在偶数边长上会把设施挂到甲板外面）；**队伍物资箱没实现**，开局不发任何物品，这条等 M3 的物资/生产系统一起做。
- 出生位置：N 队在圆周上等角分布，半径 = 海域半径 × 0.8，任意两队初始距离 ≥ 180 格直线（保证开局 90s 内不强制遭遇）。

### 4.2 建造规则 `[新增·待批 A14]`
- 只允许在**本队筏建造区**内放置/破坏方块；他人筏与公共海域禁止建造（长期服必须有这条，否则 grief 与误伤纠纷会拖垮运营）。
- 建造消耗采集到的建材（木/铁/布等），扩展筏面积会扩大建造区上限（有硬上限，防无限铺地板把服务器 TPS 拖死）。
- 筏上设施占"槽位"：设施数量随筏面积增长（例如每 9 格甲板 1 个设施位），防止小筏堆满神装。

> **实现状态（2026-11-06，M2-6 + M2-7）**：三条都已落地并且可测（`tools/build_probe.py`，
> 工程记录见 `dev/M2-RESULTS.md` §3.12 与 §3.13）——
> ①归属、阶段（只在 PLAY）、建造区（水平半径由 `limits.maxRaftArea` 换算，垂直是相对甲板 −1..+7）、
> 邻接（新方块必须贴着已有筏体）；②`maxBlocksPerRaft` 硬上限；
> ③设施位额度 = `min(maxFacilities, ⌊甲板列数 / 5⌋)`——系数由用户从"例如每 9 格"改成 **5**，
> 面积基准取**占用列数**而不是方块数（往上盖楼不该白送设施位）。
> 4×4=16 列 → 3 位，筏心自己占 1 位，所以开局只剩 2 位能摆帆或桨台，想更多必须先扩甲板，
> 这正是本节想要的"扩筏 vs 建军械"抉择；`maxFacilities` 仍是大筏的天花板。
> 另外 02 §5 的"每 1 格甲板 = 4 木 + 1 布"这条**还没接**，扩建目前不消耗资源。

### 4.3 筏体完整度与"筏心" `[新增·待批 A2/A3]` —— **本节是对原方案最重要的修改建议**

原方案沉筏规则：*筏上无幸存者 → 玩家无法复活；无幸存者且玩家死亡 → 筏 30s 后沉没 → 淘汰*。
问题（快节奏下会放大）：
1. 幸存者成为唯一复活开关 → 一旦某次交战/事件把幸存者打死，全队瞬间失去复活资格，惩罚不可逆、且与"操作水平"无关，8–15 分钟的局里很容易一次 RNG 就终结体验。
2. 淘汰路径只由"人死光"触发 → 敌方只能靠杀人取胜，无法靠"拆家"取胜，玩法会变窄成纯砍人。

建议改造（保留原方案全部要素，只把"唯一开关"改成"双轨"）：
- **筏心 = 队旗**：摧毁敌方筏心 → 触发 30s 沉筏倒计时 → 该队淘汰。→ 于是"进攻方拆筏心"成为第二条取胜路径，竞技目标清晰。
- **倒计时可中止** `[新增·待批 A3 → 2026-11-07 已删]`：~~30s 内若有人踩在筏上并用建材"重修筏心"，倒计时重置一次（每局限 1 次）。~~ → 给被偷袭的队补救窗口，符合快节奏下"失误不报废"的原则。**这条"建材重修重置倒计时"已于 2026-11-07 裁定整条删除**；保留的中止手段只有 §4.3.2 A2-v2 的"残骸修复解除倒计时"。
- **幸存者降级为加速器而非开关** `[已批准 A3]`：无幸存者时玩家仍可复活，但复活时间 15s → 30s，且复活点固定在筏心（有幸存者时由工匠接应，8s 且可选点位）。
- **反偷家保护（你的补充，已采纳）** `[已批准 A3-v2]`：**筏上仍有幸存者时，筏心受到的破拆伤害大幅降低（建议 ×0.25）**；幸存者全部失去后恢复正常破拆速率。→ 偷袭"有人守的家"基本打不动，必须先打光守筏的幸存者与人，正面冲突才有价值，"蹲家被偷"不再是无解局面。
- **初始幸存者 = 本队玩家数（你的补充，已采纳）** `[已批准 A3-v3]`：每队开局自带与队伍人数相等的幸存者。三层含义：① 开局筏上就是"有人经营"状态，生产链立刻有岗位可分配；② **口粮压力从第 0 秒存在**（N 名幸存者各自消耗水与食物）→ 这是把"必须产淡水/食物"变成硬需求的设计杠杆；③ 反偷家保护从开局即生效。数值影响见 02 §9（消耗速率与人口上限需按此重算）。

### 4.3.1 沉筏机制（正式声明 `[已批准 A3-v4]`）

**触发条件**：某队**既无幸存者存活、也无玩家存活**（全队打光）→ 该队进入 **30s 沉筏倒计时**。

**倒计时结束**：该队木筏**直接沉入海底**，该队淘汰。

**沉的表现**：筏体整体下沉到海底并停在那里，成为"沉没残骸"（§5.3 的潜水打捞收益来源）。
筏上未被取走的物资按 §5 的规则处理，**不做静默清除**。

**倒计时期间可中止**（`[已批准 A3 → 2026-11-07 已删]`）：~~30s 内若有人回到筏上并用建材重修筏心，倒计时重置一次，每局限 1 次。~~
**唯一的保留中止手段**：§4.3.2 的 A2-v2 —— 残骸持续右键 8s 恢复筏心 → 倒计时**解除**（不是重置）。
A3 的"建材重修重置"已于 2026-11-07 裁定删除，代码里 {@code SinkRule.reset}/{@code MAX_RESETS} 已移除。

#### 实现方式（技术事实，必须如实记录）

原话是"将木筏重量加大，直接沉入海底"。方向完全正确，但 Sable 里**没有任何质量写入口**：

- `MassTracker` 只有 `getMass()` / `getInverseMass()` / `addBlockMass(...)`，质量**完全由方块算出**
  （`api/physics/mass/MassTracker.java:197, :262`）
- `RigidBodyHandle` 只有冲量/速度/传送，没有 `setMass`（`api/physics/handle/RigidBodyHandle.java:78-205`）
- 全仓 `grep setMass|massMultiplier|gravityScale` **零命中**

所以"加大重量"落地为**施加一个持续向下的力**——走 Sable 自己的力管线，物理上与加重量等价
（浮力不变、向下的净力超过浮力 → 筏被压到海底），而且**不破坏筏体方块、不丢箱子内容**：

```java
QueuedForceGroup g = subLevel.getOrCreateQueuedForceGroup(NBW_FORCE_GROUP);   // ServerSubLevel.java:395（公开）
g.applyAndRecordPointForce(subLevel.getMassTracker().getCenterOfMass(),
                           new Vector3d(0, -SINK_FORCE, 0));                  // QueuedForceGroup.java:25
```

力组可自己注册（`ForceGroups.REGISTRY_KEY` + `RegistrationProvider`，`api/physics/force/ForceGroups.java:14-31`），
我们注册 `nbw:sinking`。好处：Sable 的调试可视化会把它当成一个正经力组显示出来，排查时看得见。

**替代方案（不采用）**：把甲板方块换成 `#sable:super_heavy` 标签的方块来真的增重——
字面符合"加大重量"，但会破坏玩家建造的筏体与筏上设施，且不可逆。

#### 已裁决（2026-11-05）

第二条触发路径**保留**：**摧毁敌方筏心 → 同样触发 30s 沉筏倒计时**（进攻方"拆家取胜"的路径）。
细则与新增的残骸修复机制见 §4.3.2。


### 4.3.2 筏心摧毁与残骸修复 `[已批准 A2 + A2-v2]`

**2026-11-05 用户裁决**：`[A2]` 的第二条沉筏触发路径**保留** —— 摧毁敌方筏心 → 触发 30s 沉筏倒计时。
（取消会让进攻方只剩"杀人"一条取胜路径，§4.3 的"玩法变窄成纯砍人"问题会重新出现。）

**新增机制 `[已批准 A2-v2]`**：

- 筏心被摧毁后**不消失，留下残骸**。
- 玩家对残骸**持续右键 8 秒**可恢复筏心；**必须持续**，中途松手就前功尽弃。
- **期间受到伤害即打断**。
- 筏心恢复 → 该队的 30s 沉筏倒计时**解除**（不是重置，是清除）。

#### 我替你定的默认值（不满意直接说，改一处常量即可）

| 项 | 默认 | 理由 |
|---|---|---|
| 引导时长 | 8s = 160 tick | 你给的值 |
| 打断条件 | ① 受到伤害 ② 松手停止交互 ③ 死亡 ④ 掉出交互距离 ⑤ 断线 | 你只点了"受到伤害"；③④⑤ 是"必须持续"的必然推论，②是"持续右键"的定义本身 |

#### 已裁决（2026-11-07）

`[已批准 A3]` 原本已经有一条"30s 内用建材**重修**筏心 → 倒计时**重置**一次（每局限 1 次）"。
A2-v2 的"右键 8s 恢复残骸 → 倒计时**解除**"比它强得多（解除 vs 重置，且不消耗建材）。
**用户裁定：A3 的建材重修整条删掉**。于是倒计时只剩"解除"一种中止手段；A2-v2 的"每局 1 次"
额度保留为它自己的恢复上限（不再与 A3 共享）。代码侧 {@code SinkRule.reset}/{@code MAX_RESETS}、
{@code RaftSinking.repair()}、{@code /cww raft repair} 均已移除（见 `M2-RESULTS.md` 对应章节）。



### 4.4 航行（离散位移）

`[已批准]` MVP：桨台/电鳗发电机驱动，整筏朝锁定方向平移 N 格并带走筏上玩家。
`[决策变更]` ADR-001（允许客户端模组）后，**连续/半连续航行重新可评估**：若 05 S13 证明"实体驱动筏体"（乙路线）的方块交互语义可行，可在 M2 之后升级（08 §2.4）。首发仍按离散位移实现，不在第一个里程碑就吃下最大技术风险。
- 每档动力对应单次位移格数与冷却；`[新增·待批 A5]` 电力驱动位移需耗燃料（电），使"电鳗发电机"有真实用途（呼应原方案）。
- 位移期间筏体锁定建造（防止移动中卡方块）；位移会打断正在游泳的敌对玩家（视为"被撞落"，需判定，见 05 风险文档）。
- **不做**：真实浮力、碰撞回弹、连续航迹、洋流物理。这些留给二阶段（06 里程碑 M6 之后的可选升级）。

## 5. 物资刷新体系 `[新增·待批 A4]`

原方案只说"不定期刷新各种材料装备"，缺分类与规则。建议：

| 类别 | 内容 | 稀有度分布 |
|---|---|---|
| 建材 | 木板/铁/布/油 | Common 主导 |
| 工具 | 斧/钩竿/绳/桶 | Common–Rare |
| 食物 | 生食/熟食/营养原料 | Common–Rare |
| 水 | 脏水/淡水 | Common |
| 武备 | 弩/矛/甲/弹药/炮塔件 | Rare–Epic |
| 设施图纸 | 过滤器/发电机/农场/医疗箱/修理台 | Rare–Epic |
| 幸存者 | 漂流幸存者（见 §7） | Rare |
| 特殊 | 宝藏碎片/悬赏令/事件道具 | Epic–Legendary |

- **刷出形态**：海面漂浮物（木桶、木板堆，靠近可钩取）、空投箱（事件触发，落点公开）、沉没残骸（需潜水打捞，风险换收益）。
- **点位规则**：按圈层权重生成；同一候选点若距任一玩家 > 视图距离才下发实体（防全图透视刷点，见 05 风险 R6）；`nogenerate` 区（原方案要求）严格排除。
- **防蹲点** `[新增·待批 A4]`：同一坐标连续两轮刷新后强制废弃该点位（避免"蹲Legendary"变成最优解）。

## 6. 状态机制

`[原方案]` 原版疯狂水世界是单机发展类，直接搬进竞技会不适配（如海水过滤器显得无用），因此加入营养、水分、受伤等状态，用状态把生产型道具接回来。

`[新增·待批 A5]` 三维状态 + 一条伤害线，按 12 分钟局校准（数值细节见 02 文档）：

| 状态 | 下降/触发 | 后果 | 对应生产物 |
|---|---|---|---|
| 营养 | 缓慢下降，战斗/落水加速 | 低营养 → 攻击力与移速下降、耐久消耗加速 | 食物链：农场/厨台/厨师幸存者 |
| 水分 | 较快下降 | 缺水 → 视野模糊 + 无法冲刺 | 海水过滤器 → 淡水 |
| 受伤 | 被击落/砸落/被拆方块砸中触发 | 流血（缓慢掉血）、骨折（无法冲刺/划桨） | 医疗箱、医护幸存者 |
| 失温（可选） `[新增·待批 A5]` | 长时间泡在黑海/雨中 | 加速营养与水分消耗 | 篝火/干衣 |

设计红线：**状态绝不能单独杀死满装备玩家**（12 分钟内不至于渴死饿死），它的价值只体现在"迫使分出人手去生产"，从而给生产型道具和幸存者岗位意义。这条是原方案"把生产道具融入竞技"的真正落点，必须在数值上守住。

## 7. 幸存者机制

`[原方案]` 玩家可在海域搜寻幸存者并使其加入自己木筏工作，但需消耗物资在其身上；也可让幸存者进行防御/攻击，从而缩小玩家之间个人实力差距。

`[新增·待批 A6]` 职业化（让"招谁"变成决策而不是无脑堆数量）：

| 职业 | 岗位产出 | 战斗行为 |
|---|---|---|
| 工匠 | 建造/修筏加速，重置沉筏倒计时（见 4.3） | 不参战 |
| 舵手 | 提升单次航行位移格数、缩短桨冷却 | 不参战 |
| 厨师 | 营养食物产出 | 不参战 |
| 水手 | 过滤/取水加速 | 不参战 |
| 卫兵 | 消耗口粮，无生产 | 守筏射击、拦截登筏敌人 |
| 医护 | 医疗箱产出、治疗流血/骨折 | 不参战 |

- **招募**：海面漂流的幸存者 → 用钩竿拉近/交互上筏；上筏即占用人口位。
- **消耗** `[原方案]`：每名幸存者每 30s 消耗 1 份水 + 1 份食物；人口上限 = 筏面积档位决定。
- **损失**：幸存者会死（被击杀/黑海/筏沉）；死亡只减少产能与复活加速，不再直接封死复活（见 4.3 改造）。
- **平衡意图** `[原方案]`：缩小玩家个人实力差距 → 落地为"卫兵可自动还击、医护能救回被击倒的队友"，即队伍运营好可以在 1v1 弱势时靠 NPC 补差。

## 8. 落水、救援与 PVP `[新增·待批 A1/A7]`

`[已批准]` 可自救 + 队友可救。原方案完全没有写 PVP 与落水细则，这块是海上竞技手感的核心：

- **落水触发**：被近战/远程击落、筏体位移被撞落、被爆炸/炮塔击退。
- **自救**：游到本队筏边 → 扒住边缘 → 2s 攀爬回筏（体力不足时失败，跌落伤害照旧）。
- **队友救援**：伸手（贴边 1s）/ 抛绳索（远程道具，可救远处队友）/ 钩竿拉回。
- **敌方恶意**：可打击水中玩家（伤害衰减 50%）、可用桨拍落正在攀爬的人 → 保留对抗烈度但不至于"碰到就死"。
- **黑海中的水**：消耗水分与体温加速、视野压暗、伤害递增 → 落入黑海基本等于判死，只能靠队友冒险捞人（制造高光时刻）。
- **PVP 细节**：坠落伤害保留原版；水下近战削弱；筏上战斗为主战场；禁止"自爆式拉筏"（位移中撞人伤害需要单独定值，见 05 R3）。


> **实现状态（2026-11-06，M2-8 第一 + 第二段）**：
> **自救**已落地并且可测（`tools/rescue_probe.py` 44 条全绿，工程记录 `dev/M2-RESULTS.md` §3.14/§3.15）
> ——在水里、贴着自家筏外壳、长按（真客户端）或 `cww rescue hold`（模拟），
> 2 秒（40 tick）从起爬点插值爬到**甲板面以内**的那一格（落点不再停在筏旁的半空里）。
> **队友救援（伸手）也已落地**，按你的裁决：**动作在救援方那一侧**——
> 救援方长按 1 秒（20 tick）就把人拉回筏上，这一秒他的手被占用（划桨、修筏走同一条通道，自然让位）；
> **被救者一次输入都不需要**，只要"在水里 + 够得着自家船壳"；
> 救援方的资格**只判到被救者的距离**，不判他自己在不在水里、站不站得稳。
> 仍**待批的两个数**：伸手上限 **3.5 格**、落点从船壳棱往内缩 **0.75 格**
> （玩家碰撞箱半径 0.3，正好踩在棱上会被筏子起伏挤回水里）。
> 按裁决不额外加限制，于是有两条**已知代价**（都写在工程记录里，等玩法单独裁）：
> 两个都溺水的队友可以互救，而且互救（1 秒）比自救（2 秒）快；
> 正在自己扒边往上爬的人也可以同时去拉别人。
> **本节还没做的**：①**抛绳索 / 钩竿**（02 §8 的 12 格那一档是远程道具，归武器与道具那一版）；
> ②**体力不足时攀爬失败**——玩家侧没有体力系统，硬编就是新机制；
> ③**水下近战削弱**（水中受击 ×0.5）——这版 Fabric API 只有"能不能打"与"打完告知"两类事件，
> 没有能改伤害数值的钩子，用"拦掉再补半刀"的写法会重复触发事件链，不值当；
> ④黑海相关细则归 M3。
> 另外 02 §8 那句**"双方都不能持械"没有实现**：武器表还没做，现在去查"手上是不是武器"
> 等于替玩法编定义。
> 还有：Sable 自带"sub-level 里的梯子可爬"的 mixin，但 Fabric 侧的平台判定直接返回 false，
> 所以没有移植它，扒边是我们自己的状态机；实机证明筏上梯子可爬之后再考虑换过去。

## 9. 随机事件

`[原方案]` 每间隔一段时间会出现一些事件，影响游戏局势。
`[新增·待批 A7]` 快节奏约束下的事件设计原则：
1. 事件对**全场同等生效**（不做"某队独享 RNG 收益"），避免 RNG 决定胜负。
2. 事件必须能在 30s 内被消化，不能把 12 分钟的局拖成 20 分钟。
3. 事件必须**提前 5–10s 预告**（公告 + 音效），竞技服不能出现"被暗改"。

候选事件池（首发建议 6 个，其余进后续版本）：

| 事件 | 效果 | 类型 | 首发? |
|---|---|---|---|
| 物资雨 | 圈内多点刷 Common/Rare 漂浮物，30s | 正 | ✅ |
| 风暴 | 视野压暗、远程武器精度下降、筏体位移失效 45s | 中 | ✅ |
| 海怪袭击 | 巨型实体攻击所有靠近的筏，击杀掉落 Epic 物资 | 高风险高收益 | ✅ |
| 黑海倒流 | 边界短暂外扩 20s（可回圈外抢物资），随后加速收缩 | 博弈 | ✅ |
| 幸存者聚集点 | 一处出现 3–4 名幸存者 + 一艘无人小筏 | 运营 | ✅ |
| 悬赏令 | 随机一名玩家标记，击杀者获得武备奖励（对全场公开） | 社交/针对 | ✅ |
| 宝藏碎片 | 散落 3 片，集齐开 Legendary 箱 | 探索 | ⬜ 后续 |
| 短暂安全岛 | 圈内 1 座岛 60s 中立，禁止 PVP，可交易 | 休闲/社交 | ⬜ 后续 |
| 浓雾 | 视野半径降至 20 格 | 中 | ⬜ 后续 |
| 洋流涌动 | 全场筏体被动朝某方向位移 1 格/5s | 中 | ⬜ 后续 |

## 10. 道具与生产链

`[原方案]` 热门物品移植示例：海水过滤器（生产淡水供饮用）、电鳗发电机（产生电力供木筏移动或其他用途）。

`[新增·待批 A5]` 原方案只有 2 个道具，竞技玩法需要一条最小闭环的生产链。建议首发 6 个设施 + 电力作为统一能源：

| 设施 | 耗电 | 产出/作用 | 对应状态 |
|---|---|---|---|
| 海水过滤器 | 1 | 淡水 | 水分 |
| 堆肥农场 | 0 | 营养原料 | 营养 |
| 厨台 | 1 | 熟食（增益 60s） | 营养 |
| 医疗箱 | 0 | 绷带/夹板 | 受伤 |
| 修理台 | 1 | 修筏/重置沉筏倒计时 | 筏体 |
| 桨台 / 电鳗发电机 | 产出 | 驱动筏体位移 | 航行 |

- **电力** `[新增·待批 A5]`：简化为筏级"功率池"（发电机供 N 功率，设施各耗固定值，不足则效率减半），**不做**真实电路/电线/导线实体。这条是原方案"电鳗发电机"能否落地的关键取舍：做电路会吞掉 MVP 周期。
- 生产节奏必须与 12 分钟局匹配：一次过滤器运转 ≈ 30–45s 出 2–3 份淡水，保证"必须安排人手/幸存者看管"但不吞掉战斗时间。

## 11. 社交性与休闲性（你要求"稍微考虑"）

`[新增·待批 A8/A9/A10]` 按"不挤占主线、低成本高氛围"筛选：

- **观战空投投票**（推荐，氛围收益最高）：已在打完的玩家可投票决定下一轮空投落到哪个区域，观众 → 参与，且不影响胜负公平（对所有队同等）。
- **赛后面板与 MVP**：本局建造量/采集量/击杀/救援次数/幸存者存活数，队内投票 MVP（纯社交谈资，`[已批准]` 局外只累计外观与战绩，所以 MVP 奖励给称号/外观）。
- **局内快捷沟通**：队内快捷指令轮盘（"求水""守筏""拆他家""我落水了"）+ 表情动作；不要求玩家装客户端模组，所以用原版容器 UI 实现。
- **休闲协作局**（放 M6 之后）：非 PVP 的"共建大筏/生存挑战"模式，共用同一套地图与生产链配置，纯休闲，服务打不动竞技的玩家。
- **明确不做**：局内聊天频道伪装、语音、好友推荐等，属于服务器层面而非模组层面。
