# 00 · 决策与版本选择

日期：2026-11-04 ｜ 状态：已决策（用户拍板）

---

## 1. 为什么要重来

旧计划（`Crazy-Water-World`）在"木筏移动"上走了**自研真实方块搬迁**路线，实测结论：

- 数据保真与性能都不是问题（200 步零失配、24×24 单次 1.3ms）；
- **但手感不行**：真实方块只能整格跳变，玩家靠传送跟随，画面必然抽动；
- 三家成熟方案（Eureka / Create / Valkyrien Skies）的源码都表明：**平滑来自"结构存实体 + 客户端插值/乘客同步"，而不是搬方块**。

自研这套插值 = 重造一个物理/渲染引擎，投入与风险都超出一个"小游戏模组"该承担的范围。
所以新原则：**难点工程优先依赖现成模组**。

## 3. 为什么选 1.21.1 + Sable

1. **版本与加载器都不用动**：旧计划里已跑通的地基（构建链、配置校验、内容注册、回合骨架的思路与工具脚本）可继续参考。
2. **功能最对口**：Sable 的定位就是"可交互的移动方块结构"，木筏需要的"建造 → 起航 → 站在甲板上作战 → 容器/设施可用"由它负责。
3. **成熟度最高**：690 万下载、活跃更新（2.0.6 的 changelog 就在修"站在流体上的实体"和"fabric 网络 mixin"——**正好命中我们"木筏漂在水上"的场景**）。
4. **许可可用**：PolyForm Shield 1.0.0 的禁令是「**不得提供与该软件竞争的产品**」，而不是禁商用。我们把它当库使用、做的是一个游戏玩法，不构成替代品；但**分发时必须附带条款与 Required Notice**。

## 4. 我们为此接受的风险（明确写下来，不粉饰）

| 风险 | 说明 |
|---|---|
| **侵入性** | Sable 官方原话：「Sable is an **incredibly intrusive** mod」，大量 mixin，**prone to extensive compatibility issues** |
| **黑盒依赖** | 木筏这个核心玩法的正确性交给第三方；它升级/出 bug 我们无法自行修（Shield 允许改，但改动后仍受竞争条款约束） |
| **物理不确定性** | Rapier 物理驱动的筏体，位置/碰撞不完全由我们掌控 → 竞技公平与反作弊需要重新设计 |
| **专用服务端未知** | 文档未确认 dedicated server 支持情况 → **M0 第一优先验证项** |
| **依赖链变长** | Sable 需要 ImGuiMC(LGPL)、Veil(LGPL)、Forge Config API Port(MPL)、Fabric API(Apache)；NeoForge/Fabric 双端 + 17MB 本体 + Rust 原生库 |

这些全部进 `02-风险与M0验证.md`，**M0 不通过就回到 §2 重选**（首选退路是 1.20.1 + Eureka/VS2）。
