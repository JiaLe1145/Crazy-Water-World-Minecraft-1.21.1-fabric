# 01 · 技术架构（Sable 为地基）

> 原则：**Sable 负责"方块结构怎么动"，我们负责"游戏怎么玩"。** 边界划不清，后面一定互相踩。

---

## 1. 职责划分

| 能力 | 归属 | 说明 |
|---|---|---|
| 筏体结构存储、移动、旋转、物理、随动实体、方块可交互 | **Sable**（sub-level） | 我们**不实现**任何多方块移动逻辑（旧计划的自研路线作废） |
| 筏体尺寸/形状约束、建造权限、筏心与沉没判定 | **我们**（在 Sable 之上做规则层） | Sable 提供结构，"什么算筏、谁能改、什么时候沉" 是我们的规则 |
| 回合状态机（LOBBY→ENROLL→READY→PLAY→SETTLE→RETURN） | **我们** | 纯逻辑，可单测，与 Sable 无关 |
| 黑海圈层与物资品质环带 | **我们** | 判定与数值都在服务端；Sable 只负责视觉/物理世界 |
| 物资刷新、掉落表、可见性 | **我们** | |
| 状态机制（营养/水分/受伤） | **我们** | 服务端存值 + 自建同步 + HUD 显示 |
| 幸存者 NPC | **我们**（+ 可能复用 Sable 的实体承载能力） | 站在筏上的 AI 随动是否由 Sable 处理，属 M0-3/M0-4 待验证项 |
| 武器与物品/方块注册、模型贴图 | **我们** | 玩家装客户端模组，可自由注册 |
| 配置加载与校验、持久化、命令、审计 | **我们** | 沿用旧计划里已验证的做法（校验失败拒绝加载，绝不自动纠正） |
| 反作弊与权威判定 | **我们** | **物理不等于权威**：伤害、圈内外、淘汰、建造合法性一律服务端重算（02 Q8） |

## 2. 分层（沿用旧计划里已被证明有效的部分）

```
domain/     纯玩法逻辑，零 Minecraft 依赖，可单测
            round/（阶段、转移表、队伍、席位）  zone/（圈层、环带）  status/（营养水分受伤数值）
            loot/（稀有度与权重）  raft/（筏规则：尺寸、筏心、沉没、建造区）
cfg/        arena / format / lobby JSON 模型 + 校验 + 归档 + 原子写
game/       与 MC 世界交互的适配层：注册、方块、实体、伤害、传送
sable/      ★ 唯一的 Sable 适配层（隔离区）：所有对 Sable API 的调用只允许出现在这里
ui/         容器菜单、HUD、计分板、快捷指令
net/        自定义包（版本握手、状态同步）
cmd/        /nbw 命令树与权限
persist/    局状态、战绩、外观解锁
```

**两条硬纪律**

1. **Sable 的 API 只允许出现在 `sable/` 适配层**。它升级或我们换依赖时，改动面被限制在一个包内（这是 F2「侵入性」风险的唯一防线）。
2. **domain 层不得 import `net.minecraft.*` 与 Sable**。旧计划靠这条把 61 个单测跑成纯逻辑回归，继续保留。

---

## 3. 一局的数据流

```
报名/分队(domain.round) → 生成筏：调 sable/ 适配层创建 sub-level 并放置初始甲板
   → PLAY：tick 驱动 → zone/ 算圈半径与伤害 → loot/ 采样刷点 → raft/ 判定建造与筏心
   → 玩家操作 → sable/ 执行移动 → Sable 自己负责随动与交互
   → 结算：胜负判定(domain) → 清理(局后残留断言) → 回大厅
```

## 4. 内容玩法对 Sable 能力的依赖映射（M0 之后逐条填实）

| 内容（来自 `docs/content/01`） | 依赖能力 | 等级 |
|---|---|---|
| 木筏随动力/帆/电鳗发电机移动 | 连续移动 + 玩家随动 | **待 M0-4 判定** |
| 筏上放置设施（过滤器/发电机/炮塔） | sub-level 内方块可交互 | **待 M0-6** |
| 筏心可被摧毁 → 沉筏 | 我们定义血量与判定，Sable 负责"沉"的表现 | A（可做，表现待定） |
| 幸存者站在筏上工作/作战 | 实体在 sub-level 内随动 | **待 M0-3** |
| 队伍互相接舷、登船 | 两个 sub-level 接近时的碰撞与交互 | **待 M0-4/M0-8** |
| 落水与扒筏边自救 | 我们的判定 + Sable 的表面位置 | **待 M0-6** |
| 黑海缩圈、物资刷新、状态机制、事件 | 与 Sable 无关 | A（我们自研，已有成熟思路） |

> 标 **A** 的可以直接开发；标"待 M0-x"的在验证前**不许进入开发排期**。

---

## 5. 明确不做

- 自研多方块移动、自研刚体物理、自研方块结构序列化引擎（旧路线，已被手感证伪）
- 把 Sable API 散写进玩法代码（必须走 `sable/` 隔离层）
- 让客户端参与任何玩法判定
- 为兼容而 fork Sable（除非 M0 证明必要，且要重读 PolyForm Shield 的竞争条款）
