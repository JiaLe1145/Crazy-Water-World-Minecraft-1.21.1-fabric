4. 录像：整局录屏或关键片段，命名 `run/human/<日期>_<场景>.mp4`（`run/` 不入库）。

## 5. 记录模板

每个场景记一行，**不要只写 PASS**：

```
场景：H-04 队友伸手救援
时间：2026-11-__ __:__
客户端/服务端版本：
操作：落水点在筏尾外 3 格，救援方站在甲板边缘按住右键 1.2s
观察：被拉上来的瞬间有 1 次轻微回弹；按键没有和放方块冲突
判定：PASS / FAIL / 待改
证据：run/human/20261115_reach.mp4 00:42
备注：3.5 格上限在第三人从 4 格处伸手时够不着，是否符合预期？
```

**判定口径**

- **PASS**：功能可用、没有阻断性缺陷、观感可接受；
- **待改**：功能可用但有明确体验问题（记录复现步骤与期望）；
- **FAIL**：功能不可用/会致伤/会卡死——必须回到开发修；
- **未测**：没跑到就写未测，**不许拿“代码里写了”冒充**。
