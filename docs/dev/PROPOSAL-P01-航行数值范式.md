# 提案 P-01 · 航行数值从"位移格数"改为"推力/航速"

状态：**待你批准**（未批准前不改 `docs/content/`）
背景：Sable 的 `SubLevel` 没有 setPose，移动完全由物理驱动（力、约束、推进器 `api/block/propeller`）。
旧数值表用的是"单次位移 N 格 + 冷却 X 秒"，那是自研瞬移范式的产物，挂在 Sable 上既无法表达、也丢掉了平滑优势。

## 建议改法（保持玩法意图不变）

| 项目 | 旧表述（02 §6） | 新表述 | 设计意图是否变化 |
|---|---|---|---|
| 木桨 | 位移 2 格 / 冷却 6s | 推力 P₁，**最高航速 ≈2 格/秒**，停止划桨后惯性滑行 | 不变（仍是慢、免费、可靠） |
| 帆 | 位移 3 格 / 冷却 6s | 持续推力，**航速 ≈3 格/秒**，受风向与风暴事件影响 | 不变（顺风更快、风暴失效） |
| 电鳗发电机 1 级 | 位移 5 格 / 耗 2 电 | 推进器功率 → **航速上限 ≈5 格/秒**，耗电维持 | 不变（电=航速上限） |
| 电鳗发电机 2 级 | 位移 8 格 / 耗 3 电 | **航速上限 ≈8 格/秒** | 不变 |
| 舵手幸存者 | +1 格 | **转向速率 +X%/秒**，并略微提高航速上限 | 增强：从"多挪一格"变成"更好操控"，岗位价值更实 |
| 撞角 | 位移时撞击伤害 | 改为**相对速度决定撞击伤害**（速度越高越疼） | 增强：航行本身成为武器，鼓励走位 |

## 需要新增的数值维度（旧表没有）

1. **质量**：筏体方块数/设施数决定质量 → 同样推力下加速度与最高航速下降。这让"扩筏 vs 速度"变成真抉择（旧表用"设施位上限"粗略表达，现在自然涌现）。
2. **阻力/水动**：船体在水中的阻力曲线（决定停止动力后滑行距离）。
3. **转向速率**：决定接舷与躲避的手感上限。
4. **惯性**：撞角伤害与"刹车距离"都依赖它。

## 影响面

- 改：`docs/content/02-数值与节奏.md` §6（航行）、§7（电力与设施）、`01-玩法设计.md` §4.4（航行小节表述）。
- 不改：胜负判定、圈表、状态速率、生产周期、武器表、幸存者职业——**全部保持**。
- 新增工作量：M2 需要一张"推力→航速"标定表（用 Sable 实测跑出来的，不是我拍的数），约 1–2 人日。

## 风险

物理参数是**涌现式**的，不像"位移 N 格"那样直接可控：同样的推力在不同筏体尺寸下表现不同，
配平要靠实测标定 + 埋点回归（02 §11 的回路正好用得上）。好处是手感自然、坏处在竞技服里"每艘筏速度不完全一致"，
需要在 M3 的公平回归里加一条：**同规格筏的航速方差 ≤ 5%**。

## 实测补充（2026-11-06，代码已经按这份提案的"速度控制器"路线落地）

这份提案里我推荐的第 2 条（在 Sable 之上做速度控制器）已经实现并实测，
但**提案中那几个"≈2/3/5/8 格/秒"没有照抄**——它们当时是没有实测支撑的转写，
而 02 §6 原表其实是"位移 2 格 / 冷却 6 秒"，翻译到持续位移只有 0.33 格/秒。
现在 ship 的档位是原表的逐字翻译（桨 1/3 格/秒、帆 1/2 格/秒 @风强 2，比例仍是 2:3），
上限做成 5 格/秒的保险丝而不是天花板。控制律与实测的 90% 残差见 `M2-RESULTS.md` §3.11。

三条需要你知道的事实：

1. **提案提到的"质量决定速度"这一维在控制器下不是自由涌现的**：控制器会把目标位移速度追上去，
   质量只影响逼近过程与冲量大小。要让"大筏更慢"成为玩法，得让档位随质量打折，那是新机制、需要你批准。
2. **阻尼率有两个互相矛盾的实测值**：单次冲量衰减给出 0.11~0.15 /tick，
   持续施力给出 ≈2 /tick，我还没查清原因（详见 §3.11）。控制参数按后者定，
   所以"同规格筏航速方差"这类承诺要等这个矛盾解释清楚才算验过。
3. **提案里"撞角伤害按相对速度"那条我没做**：它需要武器表（M4），而且"相对速度"取位移还是取峰值
   读数会直接改变数值口径 —— 按 §3.11 的结论应当取**位移**。
