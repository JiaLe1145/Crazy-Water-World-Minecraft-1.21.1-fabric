**依赖清单要进版本控制**：`dependencies.lock` 记录每个 jar 的版本、来源 URL、SHA、许可证、下载日期。
升级任何一个都要走灰度流程，禁止运维手抖换版本（上一轮吃过版本漂移的亏）。

## 3. 分发与版本握手

- 玩家**必须安装客户端模组**（旧计划 ADR-001 已定），推荐整合包（Modrinth App / Prism）+ 直链 jar 兜底。
- **版本/协议不匹配 = 拒绝入服并显示下载地址**，不采用"警告后放行"。
- 资源打进 jar，不发服务端资源包（避免"资源包没下成功 → 半损坏显示"）。

## 4. 运维基线

| 项 | 要求 |
|---|---|
| 备份 | `world/`（含 region 与 sub-level 数据）每 15min 快照留 24h，每小时留 7 天；战绩与配置单独备份 |
| 恢复演练 | ① 对局中强杀 → 重启恢复到当前阶段；② **移动中的筏体强杀 → 重启后 sub-level 位置与方块实体一致**（这条是 Sable 特有风险，M0-9）；③ 从备份还原整服 |
| 可观测 | TPS/MSPT、每局时长与结束原因、筏体数量与尺寸、**`moved wrongly` 频率**（Sable 相关的关键健康指标）、命令审计、局后残留断言 |
| 发布 | `changelog + 数值 diff + 回滚包`；Sable 与其依赖必须与我们的 jar 同批升级 |
| 灰度 | 测试服（脚本回归）→ 小范围真人 → 全服 |
| 反作弊 | 判定全部服务端；客户端上报只作意图；异常频率写审计，**不做自动封禁**（长期服误封代价高于漏封） |

## 5. 待你定的两件事

1. **服务器是否商业运营**（卖排名/会员/广告）？PolyForm Shield 禁的是"竞争性产品"而非商用，但我要把结论写进合规说明，避免日后争议。
2. **我们模组的许可证**（开源与否）。注意：**不能选 GPL/AGPL 与 Sable 混用**会造成分发复杂化；建议 MIT 或 Apache-2.0，并附第三方许可证声明文件。

---

## 6. 测试环境约定

- Carpet 仅测试环境（`run/mods`），**生产不装**（会改服务端行为，与竞技公平冲突）。
- **假玩家只能验证服务端数据与逻辑**；任何客户端同步类结论必须真人判定。
- 起服前先探 25565/25575 端口；收尾必须干净停服；`run/`、日志、第三方 jar 不入库。
