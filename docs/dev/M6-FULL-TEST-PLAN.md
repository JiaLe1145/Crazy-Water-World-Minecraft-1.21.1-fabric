## 执行顺序

1. **A + Q**（配置与资源，最快暴露"起不来"类问题）
2. **B + C + M**（生命周期与持久化）
3. **D–K**（各玩法系统，跑现成探针）
4. **P**（客户端实机逐个看）
5. **R + S**（性能与边界，放最后，避免影响其他测试）

## 记录方式

- 自动化：`run/probe_logs/<name>.log`，汇总 `run/all_probes_summary.txt`
- 实机：`run/_shot_*.png`
- 发现的问题：按「真 bug / 文档不一致 / 已知未结案 / 测试脚本过期」四类归档，真 bug 必修。
